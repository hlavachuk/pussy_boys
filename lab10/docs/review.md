# Перевірка та взаємне рецензування

## Виконані технічні перевірки

* Компіляція з `--release 17`, демонстраційний запуск усіх трьох сценаріїв.
* 39 автоматичних перевірок інваріантів, включно зі спробою змішати бізнес-рахунок і роздрібний тариф.
* Три UML-схеми з ролями шаблонів, ключовими полями й методами; SVG генеруються з відповідних PlantUML-джерел.
* Розширення: `StudentFactory` з продуктами не змінює `Branch`; аудиторський формувач і документ не змінюють `StatementGenerator`.

## Чекліст для реального крос-рев'ю студентами

Взаємне рецензування двома студентами ще має бути виконане командою. Авторів, підписи й вигадані зауваження не підставлено.

| Перевірка | Студент А → код Б | Студент Б → код А |
| --- | --- | --- |
| UML відповідає класам, доступам і зв'язкам | Не заповнено | Не заповнено |
| Шаблон усуває проблему з умови | Не заповнено | Не заповнено |
| Main відтворює весь сценарій | Не заповнено | Не заповнено |
| Новий сегмент/адресат не змінює загальний код | Не заповнено | Не заповнено |
| Некоректні об'єкти відхиляються | Не заповнено | Не заповнено |

Для кожного зауваження запишіть автора, файл/метод, проблему, виправлення й результат повторної перевірки. Перед захистом обидва студенти проходять усі три сценарії та пояснення з `defense.md`.
