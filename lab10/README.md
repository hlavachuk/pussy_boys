# Лабораторна робота №10

**Породжувальні шаблони: Builder, Abstract Factory, Factory Method.**
Варіант 7 — банк «Прут-Кредит». Продовження предметної області лабораторної №9: Java, окрема тека `lab10`, пакети `Task1`, `Task2`, `Task3`, спільний журнал `common.Logger`.

## Запуск

Потрібен JDK 17 або новіший. База даних, мережа та сторонні бібліотеки не потрібні.

```sh
cd lab10
./run.sh
./test.sh
```

Для Windows PowerShell:

```powershell
cd lab10
New-Item -ItemType Directory -Force out | Out-Null
$sources = Get-ChildItem src -Recurse -Filter *.java | ForEach-Object { $_.FullName }
javac --release 17 -encoding UTF-8 -d out $sources
java -cp out Main
$tests = Get-ChildItem tests -Filter *.java | ForEach-Object { $_.FullName }
javac --release 17 -encoding UTF-8 -cp out -d out $tests
java -cp out RegressionTests
```

У IntelliJ IDEA відкрийте теку `lab10`, установіть JDK 17+, позначте `src` як Sources Root та запустіть `Main`. Компілюйте лабораторні окремо: у №9 та №10 є власні `Main` і `common.Logger`.

### Гарантії реалізації

* У `build()` перевіряються непорожній клієнт, наявна додатна сума та додатний строк. Конструктор заявки приватний, поля `final`, сеттерів немає. Повторне використання будівельника не змінює готову заявку.
* `LoanDirector` містить два централізовані рецепти. Необов'язкові дані можна пропустити; мета за замовчуванням — «не зазначено» (за умовою вона не входить до обов'язкових перевірок).
* `BankingPackage` приймає лише фабрику, не окремі продукти. Перед поверненням пакета перевіряється належність усіх продуктів до одного сегмента, навіть якщо помилкова стороння фабрика повернула змішаний набір. Клієнт отримує лише перевірений пакет.
* `Segment` — відкритий тип значення, тому нова сім'я не потребує зміни enum чи коду `Branch`. Студентський сегмент додає фабрику та три продукти, а в `Main` — виклик демонстрації.
* `StatementGenerator.generate()` є `final`: відбір операцій за включними межами → підсумки через `BigDecimal` → фабричний метод → консольна імітація надсилання. Новий адресат додає лише формувач і документ, плюс виклик у `Main`.
* Надходження — сума додатних операцій, списання — модуль суми від'ємних, зміна балансу — різниця. Це не кінцевий баланс рахунку: початкового залишку в моделі немає.
* PDF представлено читабельною консольною моделлю, а не бінарним PDF-файлом; XML та CSV формують текст. Це моделювання за вимогою «без сторонніх бібліотек», реального надсилання немає. XML екранує спеціальні символи, CSV — лапки та розділювачі.
* Кожний рядок журналу, включно з багаторядковим CSV, має формат `[час] [джерело] подія`.

## Перевірка

`./test.sh` виконує 39 перевірок: обов'язкові поля та межі заявки, незмінність, типові рецепти, чотири узгоджені сімейства, відмова для змішаного пакета, включні межі періоду, точність грошей, порожня виписка, некоректний період та адресат, формати чотирьох документів, XML-парсинг і CSV-екранування. Падає з ненульовим кодом при помилці; ключ `-ea` не потрібен.
