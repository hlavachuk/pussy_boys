# Технічна перевірка та крос-рев’ю №11

## Виконаний технічний аудит

- Компіляція `javac --release 17 -encoding UTF-8 -Xlint:all`.
- Запуск кожного демонстраційного сценарію; журнал у `demo.log`.
- Перевірки поведінки та граничних випадків у `tests/RegressionTests.java`; результати у `tests.log`.
- Кожне рішення має PlantUML та SVG з відповідними класами і ролями.

## Взаємне рецензування двома студентами

Статус: очікує реального рецензування командою. Автоматична перевірка не заміняє Peer Review студентів. Розподіл завдань і авторів команда вказує за фактично виконаною роботою.

| Критерій | Студент А → робота Б | Студент Б → робота А |
| --- | --- | --- |
| UML відповідає коду та зв’язкам | Очікує | Очікує |
| Рішення усуває проблему умови | Очікує | Очікує |
| Main відтворює всі кроки сценарію | Очікує | Очікує |
| Винятки й межі оброблені | Очікує | Очікує |
| Обидва студенти пояснюють усі шаблони | Очікує | Очікує |

Для кожного реального зауваження запишіть: автор → файл/метод → проблема → виправлення → результат повторної перевірки. Не позначайте рев’ю виконаним до взаємного перегляду коду й діаграм.
