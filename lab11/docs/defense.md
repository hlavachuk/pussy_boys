# Підготовка до захисту №11

Обидва члени команди мають пояснювати всю лабораторну незалежно від розподілу завдань.

## 1. Бюро кредитних історій: Proxy

`BureauProxy` перевіряє роль до читання кешу; ключ кешу містить клієнта і робочий день. `Lending` залежить лише від `Bureau`. Три звернення менеджера дають один платний запит; касиру відмовлено навіть для кешованого результату.

Покажіть `Main.task1()`, відповідний файл у `src/Task1/`, журнал та UML. Поясніть ролі учасників і точку розширення.

## 2. Опції картки: Decorator

`Option` реалізує той самий `Card`, делегує базовій картці й додає власну ціну. Підсумки: 50 грн; кешбек + страхування + SMS = 150 грн; ліміт + бізнес-зали = 180 грн. Нова опція додає один підклас.

Покажіть `Main.task2()`, відповідний файл у `src/Task2/`, журнал та UML. Поясніть ролі учасників і точку розширення.

## 3. SWIFT: Adapter

`Treasury` знає тільки `PaymentGateway`, `Payment`, `Status`. `SwiftAdapter` централізує кодоване повідомлення та переклад A00/R17. 1000 EUR прийнято, отримувач BLOCKED відхиляється зі зрозумілою причиною.

Покажіть `Main.task3()`, відповідний файл у `src/Task3/`, журнал та UML. Поясніть ролі учасників і точку розширення.

## 4. Відкриття рахунку: Facade

`OpeningFacade.open()` задає порядок: ідентифікація → санкції → рахунок → картка → онлайн-банкінг → договір. Два `Channel` використовують цю операцію. `Cards.issue()` доступний окремо для перевипуску.

Покажіть `Main.task4()`, відповідний файл у `src/Task4/`, журнал та UML. Поясніть ролі учасників і точку розширення.
